# 迁移指南：1.2 → 1.3

AmritaCore 1.3 改变了**一轮 agent 如何结束**。工具轮次预算现在是精确的；循环不再被硬性掐断，而是收尾；原生思考的一轮也不再以一次"没有声明工具"的第二次请求收场。文末的清单列出了需要在自己代码里复查的点。

## 一览

| 变更                                              | 需要做什么                                                                                                       |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `function_config.agent_tool_call_limit`           | 现在就是字面意义上的工具轮数。依赖旧有超发的运行会少跑几轮；若当初是围着超发调的，请调高该值。                   |
| `function_config.agent_tool_refusal_rounds`（新增） | 默认 `2`。预算用尽后、本轮结束前，还允许 Agent 继续索要工具的轮数。                                              |
| `strategy.on_limited()`                           | 不再终止本轮。它会标记预算用尽，并要求模型用已有信息作答。                                                       |
| 原生思考的运行                                    | 工具轮次中会边生成边流出文本，并跳过那次独立的 completion，回复在生成过程中就到达。                             |
| `ModelAdapter.agentic_call_api()`（新增）          | 可选能力。实现它并把 `supports_agentic_call` 置为 `True`，适配器即可走新路径。                                   |

## 1. 工具预算现在是精确的

`agent_tool_call_limit` 过去允许比名字多出两轮：判断条件是 `called_count > limit + 1`。现在是 `called_count >= limit`，也就是 `10` 就是十轮工具。

step 循环的 `task_cond` 与 `iter_cond` 用同一套算法，两条工作流保持一致。

如果某个任务确实需要过去的超发量，请调高上限。

## 2. 达到预算后是收尾

`on_limited()` 过去会追加一句"不要再调用工具"，然后抛 `BreakLoop`。这让本轮没有答案，工作流于是回退到一次不声明工具的 completion 请求——而仍然想调工具的模型会把调用写进正文，而不是给出结构化调用。

现在改为收尾：

1. `on_limited()` 标记预算用尽，并要求模型用已有信息作答。
2. 下一轮仍然声明工具。
3. 模型若继续发起调用，会以拒绝型工具结果作答而不真正执行，assistant/tool 配对始终合法。
4. 若在 `agent_tool_refusal_rounds` 这样的轮次之后模型仍在索要工具，本轮才以一条提示结束。
   模型一旦给出答案就会被采纳——那条提示是兜底，不是常态。

若自定义策略覆盖了 `on_limited()`，请调用 `super()` 或自行置 `_budget_exhausted`——工作流读取的是 `budget_exhausted` 这个属性，用它决定是否放行收尾轮。

## 3. 原生思考经由循环流出

当 preset 开启原生思考**且**其协议适配器实现了 `agentic_call_api()` 时，ReAct 策略每轮只发一次请求：文本边生成边流出，该轮的工具调用在末尾返回，不返回工具调用的那一轮就是终答。该次运行会跳过那次独立的、不带工具的 completion。

其余情况沿用原有路径。原生思考的 preset 落在不具备该能力的适配器上时会记录一条 warning，因为那条路径仍可能以 §2 所述的"不带工具的请求"收场。

## 检查清单

- [ ] 如果当初是围着旧的超发量调 `agent_tool_call_limit` 的，请复查。
- [ ] 如果覆盖了 `on_limited()`，确认它仍然标记预算用尽。
- [ ] 如果自己发布适配器，实现 `agentic_call_api()` 并置 `supports_agentic_call = True` 以启用流式路径。
